# AgeCare Assessment Feature Mapping — Updated v1.5

## Functionality

The application implements multiple linked complex processes rather than only two isolated screens. The four-step New Resident Admission workflow includes validation, date selection, navigation between steps, editable Final Review sections, confirmation and immediate insertion of the new resident into the Residents list. Resident management includes working Dashboard search, Residents search/filtering, resident profiles, medication and care-plan information. Care tasks can be opened, completed/reopened and linked to resident profiles. Alerts and notifications link to related care information. Messaging includes conversation search and sending messages. Login and Logout now form a complete frontend authentication flow.

## Layout and visual appeal

The design keeps the prototype’s blue/white healthcare direction, rounded cards, status indicators and five-section navigation. The updated version adds stronger hierarchy, consistent spacing, gradients used selectively for high-level branding, improved cards and forms, clear empty states and responsive navigation. Mobile uses bottom navigation while larger widths use a NavigationRail. Forms and main pages use maximum content widths for better tablet/desktop presentation.

## Usefulness and originality

AgeCare combines time-critical aged-care workflows in one staff-focused interface: resident records, medication access, care plans, admissions, care tasks, alerts, notifications and team communication. The app reduces the need to move between separate paper or digital workflows during a shift. The additional realistic resident, task, alert and staff data makes the prototype easier to demonstrate as a practical care-management concept.

## Usability

The app uses clear labels, predictable navigation and consistent interaction patterns. Dashboard search now performs a real resident search instead of acting like a non-editable field. The Residents screen focuses directly on search, filters and profiles without repeated statistic cards. The admission workflow provides visible progress and lets users correct information from Final Review using Edit buttons. Empty states explain what to do next. Logout clearly confirms the action and returns to Login. Important status information uses both colour and text labels.

## v1.3 usability and visual refinement
The Residents, Alerts and Notifications areas now use clean white cards with colour reserved for narrow status/severity indicators and concise labels. This improves scanability without relying on large coloured surfaces. Duplicate resident actions and non-essential dashboard quick actions were removed to reduce clutter, while core navigation and complex workflows remain fully linked and responsive.

## v1.5 interface consistency and discharge workflow
Notifications and Messages now follow the same rounded white-card language as Residents and Alerts, creating a consistent professional interface. Status, severity and unread state are communicated with slim left indicators rather than full-card colour. Login and Menu content has been shortened to improve scanability. A confirmed resident discharge now removes the resident and associated open tasks/alerts, and affected screens update immediately, demonstrating a linked multi-screen state change rather than a decorative button.


## v1.4 resident and alert presentation
The Residents and Alerts screens were refined to improve scan speed and reduce cognitive load. Resident cards now use a clean white surface, large rounded corners, minimal room/age metadata and a soft translucent status rail. Alert cards show only the alert title, resident, time and a concise severity/type label. This preserves important care information while reducing unnecessary wording and visual clutter. The consistent rounded surfaces, spacing, typography and restrained colour use support the assessment requirements for professional visual appeal, usability and responsive cross-platform design.
